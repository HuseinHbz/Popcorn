### Deductions in detail

- **L1 (−0.25), named colours pass every colour check.** The ESLint regex (`eslint.config.mjs:9`, applied at `:139-149`) and the CSS checker (`scripts/check-raw-colors.ts:10`) match hex and colour functions only. Probes: `style={{ color: 'red' }}`, `style={{ backgroundColor: 'white' }}`, `className="text-[red] bg-[white]"` (Tailwind generates real CSS for arbitrary values) and CSS `color: red` all pass. This contradicts CLAUDE.md:30 ("Only design tokens for color").
- **T1 (−0.5), AC8 is not fully proven by `tests/lint-rules.test.ts`.** AC8 (`docs/stories/platform-foundation.md:23`) lists "files > 300 lines" and "packages … in `domain/` and `shared/lib`". No fixture covers either: `tests/fixtures/src/**/impure.ts` import only `node:fs` / `node:path` (core modules), and there is no long-file fixture. Probes show both rules fire (`max-lines@301`; `boundaries/dependencies` for `next-intl` in `domain/`), so this is a proof gap, not a behaviour gap. Round 1 (D-5) asked for exactly this kind of proof.
- **T2 (−0.25), AC14 says "both subsets load" but the test checks one.** `e2e/hello.spec.ts:56` asserts only `vazirmatnArabic` on `/fa` and only `vazirmatnLatin` on `/en`. Both pages render both scripts (`/fa` has the Latin "English" link and `/en` has "فارسی"), so both faces should be asserted on both pages.
- **T3 (−0.25), the first clause of AC4 is unverified.** AC4 (`platform-foundation.md:19`) says "Every user-facing string comes from next-intl". Its "Verified by" (`src/shared/i18n/messages.test.ts`) only proves that the catalogues have the same non-empty keys. Probe: a component returning `<p aria-label="Greeting">Hello world</p>` lints clean. ADR 0014's own premise is that rules enforced by review alone get missed.
- **T4 (−0.25), AC9 "every commit a push adds" has a hole on `main`.** `.github/workflows/ci.yml:9-11` cancels in-progress runs on every ref, `main` included. On `main` the commit check lints only `BEFORE..HEAD` of the newest push (`ci.yml:43-44`), so the commits of a push whose run was cancelled by a newer push are never linted.
- **S1 (−0.25), the risk register is enforced by human review only.** `docs/security/risk-register.md:3-5` says the CI gate "ignores exactly the advisories listed here" and that "an expired entry fails review". Nothing checks that `package.json:70-74` `ignoreGhsas` matches the register, or that a `Review by` date has not passed. One stray GHSA in `ignoreGhsas` would silently weaken AC13. ADR 0014 argues for machine checks for precisely this kind of rule.
- **S2 (−1.0), the Node pin is behind four security releases.** `a701e1f` (the fix for round-1 D-14) pinned `.nvmrc:1` to exactly `22.22.1`, which is the minimum `lint-staged` needs, not the current patch. `package.json:9` allows it and both CI jobs install it (`ci.yml:32,100`). nodejs.org lists 22.22.2 (2026-03-24), 22.23.0, 22.23.2 and 22.23.4 (2026-10-20) as security releases after it; 22.22.2 alone fixes two High CVEs in `http` and TLS (security round 2, N1). ADR 0014 records 22.22.1 as the baseline, and nothing tracks it: Dependabot does not read `.nvmrc`, and `pnpm audit` does not see the runtime. That fails the rubric's full-score condition (zero High/Critical).
- **S3 (−1.0), the pnpm pin carries known High advisories.** `package.json:7` pins `pnpm@10.28.0`, which `pnpm/action-setup` installs in CI (`ci.yml:29,97`). The npm advisory API returns 11 High advisories for it, all fixed in ≥ 10.34.5 (e.g. GHSA-vq4v-j7r6-jq4m arbitrary file write, GHSA-c59q-g84q-2gj5 path traversal), plus Moderate lockfile-integrity bypasses. These undermine the lockfile-integrity control the security review relies on. `pnpm audit` does not audit the package manager, so the AC13 gate cannot see them, and they are not in the risk register (security round 2, N2).

Probes in `src/modules/orders/domain/`: `globalThis.fetch('x')`, `self.crypto.randomUUID()` and `console.log('x')` pass; a `domain/*.tsx` file can call bare `fetch` (outside the `files` glob); `Date.now()` and `Math.random()` pass, although the comment at `:153` claims pure code "reads no ambient state".
