- Phase: 1 — Design System
- Plan reference: `docs/project-plan.md` §4 (Sumi & Washi); `docs/phases/phase-01.md` (PR 1.1, rescoped 2026-11-04); the approved PR 1.1 plan and the owner decisions of 2026-11-04 (final)

- Delivery: PR 0 (`chore/round-9-followups`, risk-register follow-ups; no AC here), then sub-PRs 1.1a–1.1e, each green alone. The PR column names the sub-PR that delivers each AC. PR 1.1 is ticked only after 1.1e passes review.

## Story

As the product owner,
I want every design value in one token file, and each identity's theme and accent applied at build time from settings the admin can later change,
so that the components in PR 1.2–1.4 use semantic names only, every public page stays prerendered with no flash of default colours, and the admin brand page (PR 3.6) reuses the contrast check this PR proves instead of writing a second one.

## Terms

- **Identity:** `group` (`/fa`, `/en` and every 404) or a brand, `nakaya`, `em-cafe` or `izakaya` (`/<locale>/<slug>`). Each has `default_theme`, `accent_light`, `accent_dark` and `logo` (group: none yet).
- **The nine pages:** `/fa`, `/en`, the six brand pages `/{fa,en}/{nakaya,em-cafe,izakaya}`, and the 404.
- **Theme:** `light` or `dark`. A page's theme is its identity's `default_theme` (code defaults: nakaya, izakaya and group dark; em-cafe light), set as `data-theme` on `<html>` by the route's root layout at build time. Public pages ignore `prefers-color-scheme`; v1 has no visitor toggle.
- **Theme background:** washi on light, ink on dark.
- **Accent family:** `--accent`, `--accent-hover`, `--accent-pressed`, `--accent-subtle`, `--on-accent`, derived per theme from `accent_light` (light) or `accent_dark` (dark). The only identity-specific colours; served by `/theme/<identity>.css`.
- **Check:** `checkAccent(ctx, input)` in `src/modules/brand/domain`, which validates an accent and derives its family. PR 3.6 calls it through `checkAccentFor` before every save.
- **Mark:** a traced single-colour SVG logo (`fill="currentColor"`), one per brand for both themes, provisional.
- **Sub-PRs** (`phase-01/1.1x-<slug>`): 1.1a colour science, 1.1b accent check, 1.1c tokens, 1.1d brand delivery, 1.1e brand logos.
- Test files named below are added by this PR unless they already exist.
- **Provisional values** (flagged `provisional` in tokens.json; the owner may change any later):
  - Status colours, light on washi: success `#2F6B3A` 5.58:1, warning `#7A5300` 5.98:1, danger `#8C1D40` 7.75:1, info `#2B5A8A` 6.25:1. Dark on ink: `#7FBF8A` 8.67:1, `#E0955A` 7.68:1, `#F08A8A` 7.76:1, `#8DB4E2` 8.70:1. Danger stays at ΔE_OK ≥ 0.08 from every default accent (AC9).
  - Hairline (decorative, ≥ 2:1): ash on light 2.65:1, stone on dark 2.67:1 (OQ1).
  - Type (size / line height, px): micro 12/16, caption 14/24, body 16/28, lead 20/32, title 24/32, heading 32/48, display 48/64.
  - Radius 0, 2, 4 and 9999 px; no shadow tokens.
  - Motion: easing `cubic-bezier(0.22, 1, 0.36, 1)`; fade 400 ms, reveal 600 ms, 0 ms under reduced motion; hover and pressed colour changes instant (OQ2).
  - z-index: named layers 0, 10, 20, 30, 40, 50, 60.
  - Grid: gutter 24 px; margins 24 px (mobile), 48 px (from `md`) and 96 px (from `lg`, 1280 px). The plan does not set the `md` width.
  - Accent derivation (OKLCH lightness): hover ±0.06 and pressed ±0.12, away from the theme background; subtle = the theme background moved the same way, by 0.04 on light and 0.06 on dark, with chroma ≤ 0.03.
  - Every identity's `accent_light` shu `#A8322A` and `accent_dark` kin `#B8A07A` (ADR 0019 §8), and every mark.

## Open questions

The owner decisions of 2026-11-04 and the plan's provisional values close the earlier questions, except the hairline (1) and hover/pressed motion (2).

1. **Hairline colour** (product owner, brand-designer; AC6, AC7, AC9). Plan §4 draws 0.5 px gold (kin) lines in place of cards and shadows; this PR ships a neutral hairline (ash on light 2.65:1, stone on dark 2.67:1, decorative only), flagged provisional. Kin is now only the provisional `accent_dark` and is 2.20:1 on washi. Neutral or gold, and if gold, a fixed token or the identity's accent?
2. **Instant hover and pressed** (brand-designer, product owner; AC3, AC20). Plan §4 allows only fade and reveal at 400–600 ms; this PR makes hover and pressed colour changes instant (provisional). Is that acceptable? To confirm in the PR 1.2 Storybook.
3. **Accent near the danger red** (product owner; for PR 3.6, not a rule of this PR's check). The defaults keep each theme's danger colour at ΔE_OK ≥ 0.08 from every default accent (AC9). Should the PR 3.6 save also reject an accent close to danger, and at what distance?
4. **Attributes allowed in the traced marks** (architect, security-reviewer; AC22; needed before 1.1e). The plan fixes the elements (`svg`, `g`, `path`) and `fill="currentColor"`, with nothing else. Tracing tools commonly also write `fill-rule`, `transform`, `width`/`height`, `id` or `<metadata>`. Will the owner export marks with path data only, or does the allowlist grow, each addition with a rejection fixture? The marks are not in the repo yet.
