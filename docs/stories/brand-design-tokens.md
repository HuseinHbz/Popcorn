# Story: Design tokens and runtime brand theme (PR 1.1)

- Phase: 1 — Design System
- Plan reference: `docs/project-plan.md` §4 (Sumi & Washi); execution plan `docs/phases/phase-01.md` (PR 1.1, rescoped 2026-11-04)
- Decision: `docs/adr/0019-runtime-brand-identity.md` (Proposed); related ADR 0012, 0015, 0017

## Story

As the product owner,
I want every design value in one token file, and each brand's accent applied by the server from a value the admin can later change,
so that the components in PR 1.2–1.4 use semantic names only, no page flashes default colours, and the admin brand page (PR 3.6) reuses the contrast check this PR proves instead of writing a second one.

## Terms

- **Theme background:** washi on the light theme, ink on the dark theme.
- **Accent family:** `--accent`, `--accent-hover`, `--accent-pressed`, `--accent-subtle`, `--on-accent`, derived per theme from that theme's accent (`accent_light` on light, `accent_dark` on dark). It is the only thing set at run time.
- **Check:** the pure function in `src/modules/brand/domain` that validates an accent and derives its family. PR 3.6 calls it before every save.
- Test files named below are added by this PR unless they already exist.

- The nonce-based CSP itself: Phase 2 (risk register), unless OQ1 brings it forward.

- Hi-fi mockups and the phase gate (design score, restaurant approval): outside Claude Code.

## Open questions

1. **CSP nonce and how the brand style is injected** (architect, security-reviewer; needed for AC17, AC21). `phase-01.md` says the injected `<style>` carries the CSP nonce, but no nonce exists before Phase 2 (risk register), and a nonce makes every page render per request, where `/fa` and `/en` are prerendered today. ADR 0015 also bans a JSX `<style>` child expression, so a `<style>` block needs a lint override with an ADR link. Options: (a) a `<style>` block now under today's `'unsafe-inline'`, with the nonce added in Phase 2; (b) the variables in the `style` attribute of `<html>`, which lint allows, but a nonce cannot cover an attribute, so a strict Phase 2 policy would still need `'unsafe-inline'` or per-value hashes in `style-src-attr`; (c) a per-brand stylesheet served by a route, under `style-src 'self'` with no nonce and cacheable per brand, at the cost of one render-blocking request (measured against AC26). Which one, and does ADR 0019 §4 need amending?
2. **What makes a page dark** (product owner; needed for AC19, AC24–AC26). The visitor's `prefers-color-scheme`, an attribute the server sets (the admin defaults to dark in PR 1.4), a visitor toggle, or a combination? Public pages are light-only today, so following the system setting turns them dark for some visitors. A theme kept in a cookie makes pages render per request; one kept in client storage flashes. The answer also fixes how Playwright and Lighthouse select the dark theme.
3. **Dark-theme form-control border: stone or ash?** (product owner; AC7). Stone passes on washi (6.14:1) but is 2.67:1 on ink, below WCAG 1.4.11's 3:1. Ash is 6.17:1 on ink but 2.65:1 on washi, so no single neutral serves both themes. AC7 requires ≥ 3:1, which on ink only ash (or washi itself) meets; choosing stone means waiving 1.4.11 for control borders on the dark theme.
4. **Accent as normal-size text** (product owner, brand-designer; AC9, AC11; must be answered before PR 3.6). The check accepts an accent at 3:1 on its background, but normal-size text needs 4.5:1, and the home and 404 links are accent-coloured text (they pass with the defaults: 5.81:1 and 7.45:1). Options: (a) the accent never colours normal-size text; (b) a derived `--accent-text` that meets 4.5:1; (c) a 4.5:1 floor for the accent. Also: the two rules together reject every accent above 3.63:1 and below 4.5:1 on its background, because the ink and washi ratios on it multiply to 16.36 and neither reaches 4.5:1 (AC13 fixture). The PR 3.6 admin copy should explain this.
5. **Accent for pages with no brand** (product owner; AC17). `/fa`, `/en` and the 404 belong to the group, not one brand. Once the brands' accents differ, which do these pages use: the code default, one brand's, or a group entry of their own in `brand_settings`? The three defaults are equal today, so the answer is not visible yet.
6. **Hairline colour** (product owner, brand-designer; AC6). Plan §4 draws 0.5 px gold (kin) lines in place of cards and shadows. ADR 0019 keeps only ink, washi, stone and ash as fixed colours, and kin is now only the provisional `accent_dark`. Should lines be a fixed kin token (2.20:1 on washi, so decorative use only), the brand accent, or a neutral? The home page separator (`border-kin` today) follows the answer.
7. **Values the plan and ADR 0019 leave open** (brand-designer, product owner; AC2). Status colours (a light and a dark value each, and how error red stays distinct from the shu accent on the light theme), type scale, radius, elevation (none, or a shadow for the PR 1.2 Dialog and Sheet), easing curve, z-index layers, grid gutter, mobile margin and the breakpoint where the 96 px margin starts, and the OKLCH offsets for hover, pressed and subtle. Plan §4 sources them from the Design System artifact: will it be approved in time for this PR? Until then they ship flagged `provisional`.
8. **Do hover and pressed changes count as motion?** (brand-designer; AC3, AC20). Plan §4 allows only fade and reveal at 400–600 ms; button feedback that slow may read as lag. Instant, a separate short duration, or 400 ms? Needed before PR 1.2.
9. **Logo variants** (product owner; AC22). One variant of each logo arrived: Nakaya and Izakaya white on black, em. café black on white; the other variant is an inversion. Does the owner approve the inverted variants, and are the marks pure black and white or ink and washi? The source canvases carry wide padding (the Nakaya mark fills about a third of its 1,080 px height): trim to the mark and apply clear space in the layout? What clear space and minimum size do the brand rules set (Izakaya's "ASIAN KITCHEN & BAR" line becomes unreadable when small)? The brand guide is still open in plan §11.
10. **Where `BrandLogo` renders in this PR** (product owner; AC24). (a) The home page's brand list, which adds E2E, axe and Lighthouse coverage and changes the placeholder page; or (b) nowhere until SiteHeader (PR 1.3), with AC24 moving to the PR 1.2 Storybook story.
11. **ADR 0019 is Proposed and not reviewed.** This story assumes its Decision §1–§5 and §8 as written; a review change there changes AC9–AC18.
