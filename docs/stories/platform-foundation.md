# Story: Platform foundation (Phase 0)

- Phase: 0 — Kickoff and infrastructure
- Plan reference: `docs/project-plan.md` §8 (Phase 0); execution plan `docs/phases/phase-00.md` (PR 0.1–0.4)

## Story

As the product owner,
I want a repository with an enforced toolchain, local services and a CI pipeline,
so that every later phase starts from green gates instead of setting them up ad hoc.

## Out of scope

- Nonce-based CSP without `'unsafe-inline'`: it needs the dynamic-rendering trade-off, is decided with auth in Phase 2, and is tracked in `docs/security/risk-register.md`.
- Design tokens pipeline (`tokens.json` → Tailwind) and the type scale; the Peyda files themselves (licence pending) — Phase 1.
- Database schema, migrations and the app's first use of `env` values — Phase 2.
- Production Dockerfile, Nginx and deployment — Phase 5.
- Deviation from `phase-00.md` PR 0.2: MinIO is replaced by SeaweedFS because MinIO images are no longer published (ADR 0013, proposed).

## Open questions

Blocking items for closing Phase 0 are the business questions in plan §11 (SEP Terminal ID, Sepidz/Rahkaran API access, deposit policy, loyalty rules, initial `charge_rules`, vector logos, Peyda licence scope).
